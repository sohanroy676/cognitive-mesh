# System Patterns

## Naming conventions
- Package `cognitive_mesh` (import), `cognitive-mesh` (distribution and console script).
- Env vars: `COGMESH_` prefix, except the conventional `GROQ_API_KEY`.
- Tests: `tests/test_*.py`.

## Folder structure logic
- `src/` layout: all product code in `src/cognitive_mesh/`; tests in `tests/`.
- Significant decisions go in `docs/adr/` (0002-0004 cover tooling and config, 0005 ingestion, 0006 dependency graph, 0007 JS/TS, 0008 visualization, 0009 agents, 0010 orchestrator, 0011 trace store, 0012 Ollama, 0013 Groq, 0014 semantic memory retrieval).

## Common patterns used in this project
- Configuration is read only through `cognitive_mesh.config.load_settings()`; never `os.environ` directly elsewhere.
- Secrets are `SecretStr`; never log or print them, and keep them out of error messages.
- Config failures raise `ConfigError`; the CLI maps them to exit code 2 (0 = ok).
- Tests run via an autouse fixture (`tests/conftest.py`) that clears config env vars and uses an empty temp cwd, so a real `.env` never leaks in.

- Ingestion (`cognitive_mesh.ingestion`, ADR-0005): per-file problems are `Diagnostic`s, never exceptions; only a bad root raises `IngestionError` (CLI exit 3). Ingested content is data: never imported, executed or put in diagnostics (not even parser error text). All file reads go through `ingest._read_bytes`; tests spy on it to prove sensitive files are never opened.
- Every ingested record carries a `SourceRef` (relative POSIX path + sha256 of the original bytes) and the rule that classified it. Secrets found in content are replaced by `[REDACTED:<rule>]`; the sha256 still refers to the original bytes.
- Test fixtures: benign app committed in `tests/fixtures/sample_app/`; hostile files (secrets, binaries, malformed) are created in `tmp_path` at test time, and fake secrets are assembled at runtime. Keep parametrize ids short (huge inputs in ids break pytest on Windows).

- Changelog: `CHANGELOG.md` is generated by git-cliff (`cliff.toml`), never hand-edited. Regenerate as the very last commit of a branch (`chore(changelog): regenerate`); any later non-merge, non-`chore(changelog)` commit makes it stale and CI fails. Use `fix`/`feat`/`docs`/`build`/`ci` for things that belong in it; `chore(deps)` is skipped by design.
- Versioning: never hardcode a version. The version is the latest `v*` git tag (hatch-vcs); a release is made by tagging. `__version__` is read from installed metadata, so after tagging re-run `uv sync` to refresh an editable install.

- Providers (`cognitive_mesh.providers`, ADR-0012): clients implement `ModelClient` and raise only `ProviderError` with fixed messages (kind or HTTP status number, never a request, reply, body or exception text; raise with `from None`). HTTP goes through the private `HttpTransport` (`providers/http.py`): one monotonic deadline for the whole call, enforced by a timer that shuts the socket down; no redirects or retries; errors are `TransportError(kind)` only. Tests inject a fake transport (`tests/test_providers_ollama.py`) or use a 127.0.0.1 socket server (`tests/test_providers_http.py`, `tests/test_cli_model.py`); canary strings in prompts/bodies must never appear in errors, output or traces. `run` builds a client only when the plan has a model step and a provider is set (`cli._registry_for`). Real-provider tests carry the `live` marker plus an env var and are skipped by default. Failure mapping for every client lives in `providers/errors.py` (`status_error`, `transport_error`, `bad_reply`); a new client must use it and gets a parity test against the others (`tests/test_providers_groq.py`). Groq (ADR-0013): fixed HTTPS endpoint constant, key held as `SecretStr` and put in the `Authorization` header only inside `complete()`, `<think>` in a reply is rejected, never stripped; CLI tests replace `cognitive_mesh.providers.groq.StdlibTransport` so no test reaches the network.

## Things to avoid
- Hardcoding credentials or committing `.env` files (only `.env.example`, placeholders only).
- Documenting commands that have not been run successfully.
- Marking a roadmap version done before its verification criteria pass.
- Dependency graph (`cognitive_mesh.graph`, ADR-0006): `A -> B` always means "A depends on / imports B". Every `Edge` has >=1 `Evidence` (SourceRef + line + rule + cited text); the model rejects none. Anything not resolvable becomes an `unresolved` node plus a diagnostic, never a guessed edge; imports are never linked to packages by name. Builders (`graph/builders.py`) are pure over `IngestionResult` and never touch the disk. NetworkX stays private to `graph/graph.py`; public API returns frozen pydantic models; outputs are sorted for determinism. Only `GraphError` (unknown node id) is raised (CLI exit 4).
- JS/TS and dynamic imports (ADR-0007): tree-sitter is imported only in `graph/js_parse.py`, which returns plain `JsImport` records; matching is on syntax nodes (never regex/text) so comments, strings, template text, regex and JSX text cannot create edges; the walk is iterative; nodes in ERROR subtrees are skipped and reported as a `parse_error` warning. A dynamic import whose target is not a plain literal becomes `unresolved:dynamic:<path>:<line>` plus a `computed_import` warning, never a guessed edge. Bare/aliased JS specifiers stay `unresolved:import:js:<pkg>` (the npm `candidate_package` is a hint only). `.js` is never remapped to `.ts`.
- Test fixtures: `tests/fixtures/js_app/` holds the JS/TS fixture (decoy imports in comments/strings/regex/JSX that must never become edges). Do not write big files in tests without checking Windows speed: opening a fresh 880 KB file took ~23 s here.
- Visualization (`graph/view.py`, `render_mermaid.py`, `render_html.py`, ADR-0008): renderers are pure functions of a `GraphView` made by `build_view`, which only selects from the graph (never adds or rewrites). Graph text is untrusted: HTML uses `esc()` (visible escapes, HTML escape, `&#N;`) in text nodes only; ids/classes are generated and CSS is constant; Mermaid never uses graph text as an identifier and entity-encodes everything outside a safe set. Output is ASCII/LF with no absolute paths or timestamps. Truncation is always announced. Any new renderer needs hostile-name tests (see `tests/test_graph_render.py`) and must leave text/`--json` output unchanged. In `graph/__init__.py` the names `render_html`/`render_mermaid` are the functions, not the modules (patch via `sys.modules` in tests).
- Test fixtures: `tests/fixtures/expected/` holds golden outputs (`dep_app.mmd`, `js_app.mmd`, `dep_app.txt`); regenerate only after reviewing the diff.
- Test fixtures: `tests/fixtures/dep_app/` is the graph fixture (cycle a<->b, undeclared and declared imports, `-r`/URL requirement lines); `tests/fixtures/` is excluded from mypy.
- Orchestrator (`cognitive_mesh.orchestrator`, ADR-0010): `plan_task` is the only way to get a `ValidatedPlan` (the runner accepts nothing else); plan problems raise `PlanError` naming step ids only, before anything runs. `Orchestrator.run` never raises: agent exceptions and results that are not an `AgentSuccess`/`AgentFailure`, or whose agent/task/capability ids do not match, become `failed` steps (`agent_raised`/`invalid_result`) and are never retried. `TaskRun.status` is a computed property over the step statuses (succeeded only if all steps succeeded), never a stored field. Retry only on `AgentFailure.retryable`, at most `MAX_ATTEMPTS_CAP` (5) per step. Time and sleep are injected (`clock`, `sleep`); tests never sleep. A step whose prerequisite failed/blocked is `blocked`; one whose prerequisite is `not_run` is `not_run`. Orchestrator tests use `Scripted` fake agents (see `tests/test_orchestrator.py`).
- Traces (`cognitive_mesh.traces`, ADR-0011): `sqlite3` is imported only in `traces/store.py`; every statement is parameterized and errors are wrapped in `TraceStoreError` with fixed messages (no SQL, no stored values). A run header is committed as `running` before the run; steps, attempts and the final status are written in one transaction, so a crash or rollback reads back as `interrupted`. Status is never trusted from storage: `RunTrace.to_task_run()` recomputes it from the steps and a disagreement, or any column that contradicts its JSON (agent id, task id, model info), is a `TraceRecordError` (`list` reports bad runs as `malformed` instead of hiding them). Everything stored goes through `redact_json` first (rule names recorded, never values). Readers (`TraceStore.open_existing`) never create a database; only `create` does. Tests corrupt rows with direct SQL (`CORRUPTIONS` in `tests/test_traces.py`); add a case there for every new check. Orchestrator timestamps exist only when `Orchestrator(now=...)` is given, so `run --json` without `--trace-db` is unchanged.
- Agents (`cognitive_mesh.agents`, ADR-0009): every agent is a table of `Capability` (input model, output model, handler); `spec()` is derived from the table. `Agent.run` never raises; expected problems are `AgentFault(kind, message)` raised in handlers, anything else is `internal_error` naming only the exception type. Messages never contain input values, file content, model text or exception text; unknown input keys are shown as `<input>`. `AgentTask` ids are pattern-restricted so they are safe to echo. Inputs validate with `strict=True`, `extra="forbid"`. All provider handling is `agents.base.call_model` (never in a role); agents import only `providers.ModelClient`. Model output is parsed as strict JSON into the output model; a model-backed success is `model_unverified`. File content goes to a model only as a JSON-encoded string with an "untrusted data" system note. Tests use fake clients; no test touches the network.
- Trace-store migrations (ADR-0011 amendment): schema changes are `MIGRATIONS[n]` scripts (n -> n+1) in `traces/store.py`, append-only once released; writers (`create`) apply them atomically per step, readers (`open_existing`) never modify and report an older version, a newer database is refused. Tests patch `store_module.MIGRATIONS` (see `tests/test_trace_migrations.py`).
- Lockfiles (ADR-0005/0006 amendments): only `uv.lock` and `package-lock.json` (v2/v3) are read, in `graph/lockfiles.py` (pure, stdlib only, returns packages and evidenced dependencies; the builder applies them as `requires` edges). `transitive_unknown` is per ecosystem without a readable lockfile. Entropy rule skips `sha256-/384-/512-` integrity hashes.
- Orchestrator data flow (ADR-0010 amendments): `input_refs` are checked in `planner._check_refs` before anything runs and resolved in `runner._resolve_inputs`; the producing result's `basis` is recorded in `StepRecord.input_sources` (not persisted). Fallback goes to the next agent of the same capability (max 3), only after a failure result; raised/invalid results and budget expiry are terminal. Trace attempt ids keep the step-wide count.
- Plan drafting (`orchestrator/generate.py`): request and capability catalog go to the model as one JSON string, reply must be exactly `{"steps": [...]}` and pass `TaskPlan` (strict) and `plan_task`; errors hold fixed text and ids only; nothing is executed.
- Remote content: `COGMESH_ALLOW_REMOTE_CONTENT=true` is required to build a Groq client (`providers/factory.py`); Ollama is exempt.
- Memory (`cognitive_mesh.memory`, ADR-0014): `chromadb` is imported only in `memory/index.py` and `sentence_transformers` only in `memory/embedder.py` (lazily, so only `memory` commands pay for it; `cli._make_embedder` is the seam tests replace with `FakeEmbedder` from `tests/memory_support.py`). The SQLite trace db is authoritative; the index is a derived copy keyed `run_id/step_id/attempt_no` with the sha256 of the embedded text. `search` re-reads each hit via `TraceStore.get`, rebuilds the document and returns it as a hit only if the hash still matches; otherwise it is an `UnverifiedHit` (`source_missing|source_changed|source_unreadable`). The collection records model name, revision, dimension and `TEXT_FORMAT_VERSION`; any mismatch raises `MemoryIndexError` (CLI exit 11) and nothing is mixed. Changing the embedded text format means bumping `TEXT_FORMAT_VERSION`. Readers never create an index. Results always carry `SIMILARITY_NOTE`. Real-model checks are opt-in (`RUN_LIVE_EMBEDDINGS=1`).
- HTML layout: `render_html.order_layers` (barycenter sweeps) and `crossings`; layer membership never changes.
