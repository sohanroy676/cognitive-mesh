## Recent decisions
- ADR-0017 (accepted by the user): context supply. `RecalledContext` (frozen, pydantic only) rides on `AgentContext.recalled`; claims keep status, meaning and run/doc ids on both sides; failed and model-written runs are a raw group with metadata only; unconfirmed hits are counted, not sent. Relevance gate: a claim is offered only if its subject exists in the current dependency graph, a raw trace only if its run's root directory has the same name; the rest is listed for the person. `code_explainer` gets the pack as untrusted `prior_context`; `compare_with_recalled` (deterministic) re-checks claims with the shared `graph/rederive.py` and is not mapped to claims. Trace schema 1 -> 2 stores the pack and the request length with the run (request text never stored); index and graph are refreshed by hand. `task` creates the trace store before recall, runs with an explicit empty pack on a first session, and treats an existing but unusable index, graph or reviews file as an error (exit 11/12/15). Limits: node ids plus directory name, not application identity; the cut-off 0.2; whole-graph recall per call; nothing verifies what a model does with the pack.
- ADR-0016 (accepted by the user): evidence-aware retrieval. Statuses (`conflicting`, `validated`, `unsupported`, `stale`, `supported`) are categories computed per code version on every call, never stored, never a number; only attempts whose source check is ok count. Validation = re-derivation from `--root` by the same analyzer, or a person's `confirmed` review for that fingerprint (neither is proof). Conflicts = a complete (`coverage=complete`) listing that lacks the claim; same fingerprint conflicts, another fingerprint is shown as a difference across versions; truncated listings never contradict; rejected reviews and refuted re-derivations count as contradiction. Reviews: separate append-only SQLite file (`--reviews`, exit 15). `recall` needs no provider; claims, raw experiences and unconfirmed hits are separate groups; similarity is shown only as "retrieved via". Graph format 2 (older files refused). Limit: the graph does not record the application, so equal node ids from different apps merge.
- ADR-0015 (accepted by the user): experience graph in `experience/`. Nodes: run, step, final attempt (shares the v0.7.0 `doc_id` and text hash), capability, agent, target, claim. Claims only from successful `deterministic` `dependencies_of` (depth 1) and `unresolved_report` outputs, always `unvalidated`; the same claim from several runs is one node with several `evidenced_by` edges, each with the run's source fingerprint. Separate SQLite file (`--graph FILE`, `application_id`, own schema version; trace db untouched, `MIGRATIONS` unchanged). Load refuses a foreign file, a newer version, malformed records, dangling edges and a hash mismatch (the hash also covers build diagnostics). Dangling sources are kept, marked `source_missing|changed|unreadable`, and hidden unless `--include-unverified`.
- ADR-0014 (accepted by the user): semantic retrieval over traces. Eligible = final attempt of succeeded/failed steps of finished runs; pinned `all-MiniLM-L6-v2`; chromadb + sentence-transformers runtime deps with CPU torch on Linux; explicit `--index DIR`; Chroma id `run_id/step_id/attempt_no` + text sha256; every hit re-verified against SQLite; other-model index refused (exit 11); cut-off `--min-similarity` default 0.2 (rough, from 3 documents); amendments: no env setting, `source_unreadable`, torch as direct dep.
- ADR-0012 (accepted by the user): stdlib `http.client` transport with one total deadline per call (timer shuts the socket down; also stops slow-drip headers); `OllamaClient` maps timeout/refused/5xx/429/401-403/404/other 4xx/malformed to `ProviderErrorKind` with fixed messages; settings `COGMESH_OLLAMA_MODEL` (default `llama3.2`) and `COGMESH_MODEL_TIMEOUT_S` (default 30, max 600); `run` reads config only for plans with a model step (no `COGMESH_PROVIDER` keeps the old `provider_unavailable`, exit 7; any other config problem exits 2; `groq` exits 2 until v0.6.2); no logging added; live test needs the `live` marker and `RUN_LIVE_OLLAMA=1`.
- ADR-0011 (accepted by the user): SQLite trace store, stdlib `sqlite3` only; opt-in `run --trace-db`; run committed as `running` first and finished in one transaction (a crash reads back `interrupted`); status recomputed and cross-checked on read, malformed rows raise or are reported by `list`; secrets redacted before storing; per-step timestamps only when the orchestrator has a `now` clock; exit 8/9.
- ADR-0010 (accepted by the user): sequential orchestrator; plans validated before running; assignment by `registry.find(cap)[0]`; steps `succeeded|failed|blocked|not_run`; task status derived from steps; retry only `retryable` agent failures (default 2, cap 5); invalid results and raised exceptions fail the step and are not retried; run budget checked before each attempt (no watchdog); `depends_on` is ordering only; `run` CLI exits 6/7.
- ADR-0009 (accepted by the user): agents depend only on the `providers.ModelClient` protocol; `Agent.run` never raises; results are `AgentSuccess | AgentFailure` with explicit failure kinds; capability specs are derived from the handler table; messages never contain input values, file content, model text or exception text; model-written output is `model_unverified`; timeouts are provider-owned (no watchdog).
- ADR-0008 (accepted by the user): Mermaid and self-contained HTML/SVG from one `GraphView`; no new dependency, no script or network loads; escaped, ASCII, deterministic output; visible truncation (HTML 300/1000, Mermaid 100/200); `--format` is exclusive with `--json`/`--deps-of`; exit 5 for write errors.
- ADR-0007 (accepted by the user): tree-sitter for JS/TS, private to `graph/js_parse.py`; syntax-node matching only; computed dynamic imports are `unresolved:dynamic:*` + `computed_import`; bare/aliased JS specifiers stay unresolved; no `.js`->`.ts` remap.
